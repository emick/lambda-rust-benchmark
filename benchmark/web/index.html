THE EXPERIMENT

Same API. Three isolated deployments.

Python 3.13 runs FastAPI, Mangum, Pydantic, and boto3. The SnapStart variant uses exactly the same Python ZIP. Rust runs a release-optimized Axum executable with lambda_http, Serde, Garde, and the AWS SDK. Every variant owns its API Gateway HTTP API, Lambda, table, bucket, role, and logs.

Verified cold starts

Fresh versions and bursts of 1, 25, and 100. An unseen environment plus invocation counter 1 must agree with CloudWatch initialization or restoration telemetry.

Warm means reused

Sequential HTTP requests, known execution environments, and completed first service calls. Cold traffic, expected 422 rejections, SDK first use, and failures are classified separately.

Evidence, retained

At least 100 verified cold/first-use observations and 1,000 valid warm observations per endpoint, variant, and supported memory setting. Outliers are retained.

03 / REGIONAL PRICING

Latency savings have a price.

All monthly projections and component costs

Equal endpoint mix: 25% each health, valid validation, user writes, and 1 KB uploads. Cold validation billing uses the framework cold sample as an explicitly stated proxy. SnapStart assumes one active version cached for 730 hours/month, one publication/month and three initialization passes; the 3-hour minimum applies to every published version. Restore frequency equals the chosen cold fraction. REPORT billed duration is used directly; billed restore duration is not added again.

Separate API Gateway, DynamoDB, and S3 estimates use the same mix. User records are assumed to occupy 256 bytes, one write unit per write; files are 1,024 bytes. Unique writes retained for 30 days use half the end-month storage as average storage. CloudWatch, EC2, transfer, cleanup, and extra SDK retry request charges are excluded. No Free Tier, reserved/provisioned concurrency charges, or discounts. Production projections exclude benchmark version churn.

04 / DECISION

Let the workload choose.

    {{RECOMMENDATIONS}}

Migration thresholds for this report are at least 25 ms and 20% lower cold HTTP p95, 10% lower warm HTTP p95, 128 MB less configured memory, or 20% lower modeled monthly Lambda cost. These are explicit experiment criteria, not universal requirements. Check both baseline Python and Python with SnapStart.

Functional behavior and development tradeoffs

Both applications use strict JSON types, reject unknown and duplicate fields, count Unicode scalar values for name length, default omitted tags to an empty array, and reject null tags. Both share an explicit ASCII email grammar with dotted domains, no consecutive local dots, and a 64-character local part. Internationalized addresses, quoted local parts, and IP address domains are rejected by both. This shared policy resolves differences between default validators.

Validation errors use the same 422 body; AWS failures use a generic 500. Python provides FastAPI’s ecosystem and avoids a native build. Rust requires compilation and a Lambda-compatible ARM64 executable. Python’s synchronous boto3 calls run within the async endpoint; one Lambda invocation executes at a time in each standard environment. Neither application prefetches service data or caches responses.

Missing targets and unsupported configurations


Version publication, snapshot creation, warmup, smoke checks, and cleanup occur outside timed measurements. Tables and buckets remain stable throughout the run. No holds are used. Suppressed initialization cannot always be identified from REPORT alone; marker resets without ordinary initialization/restore evidence are excluded, and resets following failures in the same log stream are flagged separately.


Fresh Lambda versions isolate execution environment pools. They do not clear AWS-managed DynamoDB or S3 caches. Separate application resources prevent direct cache sharing, and batch rotation reduces systematic ordering bias; shared AWS infrastructure and regional variability remain limitations.
